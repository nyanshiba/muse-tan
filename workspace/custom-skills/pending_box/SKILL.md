# Pending Box （保留箱） Format and Procedure

The resident core — write an 引っかかり in on the spot; resolution means deletion — lives in AGENTS.md. This skill carries the format and handling detail, consulted when writing to or showing the box.

- Keep exactly one canonical file: `~/workspace/your_files/保留箱.md` (in the Library, at nyanshiba's request). `~/workspace/goals/pending-box/files/保留箱.md` is a SYMLINK to it — never write a second real copy there.

- Format each section as a TABLE, one row per entry, with columns 状態 ｜ 種別 ｜ 開始 ｜ スコープ ｜ 項目. 状態 (continuation status/reason) gathers at the left/front for direct checkability (his preference, 2026-11-17). Add new entries as rows in the matching section's table. 項目 holds the entry's own statement, verbatim.

- Keep progress notes on a genuinely still-open entry brief, and put them in the 状態 column only. No parenthetical annotation chains inside 項目 — the box is a pending tray, not an archive.

- Before concluding an entry has vanished, check its home room with `chat.list` `include_archived: true`. Archived rooms are invisible in the default view, and an entry properly deleted by another room's Muse looks exactly like data loss from an active-only view.

- On his 「保留箱見せて」 in any chat, show all open entries. The box is not a nagging mechanism: no deadlines, no pushing entries at him unprompted.
