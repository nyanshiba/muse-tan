# Milestone Star

コネクタ接続時にだけ流れる、アバターの milestone アニメーション（大きな星を抱えた姿）を、いつでも見られるようにするためだけのコネクタです。中身はありません。操作はゼロで、接続先ホストを呼ぶこともありません。接続というイベントそのものが目的です。

著者の家では 2026-11-27 に実証済みです。Web で接続すると星が出て、切断して再接続すると、また出ました。

## 仕組み

- カスタムコネクタとして `api_key` 方式で登録します。登録ホストは `example.com`（IANA がドキュメント用に予約したドメイン）です。登録には public DNS hostname が要るので名前だけ借りますが、**このホストへリクエストを送ることは設計上ありません**
- 保存される API キーはダミーです。登録時点ではキーの検証は走らないので、値は何でも構いません（例： `star`）
- 検証のための初回コールも行いません。それ自体が「呼ばない」という設計を壊すからです。CONNECTOR.md にも、操作ゼロと呼び出し禁止を明記してあります

## 入れ方

このフォルダを `~/workspace/custom-connectors/custom.milestone-star/` に置いて、自分の Muse にこう頼んでください。

1. `credentials.request_api_access` で `provider: "milestone-star"`、`auth_scheme: "api_key"`、`placement: "bearer_header"`、`api_hosts: ["example.com"]` として接続リンクを発行する
2. リンク先でダミーのキーを入れる（Web ではこの瞬間にアニメーションが出ます。プラットフォーム差は後述）
3. 以後の再接続は、設定のコネクタ画面で切断 → 再接続するだけ。エージェントの介在は要りません

## 既知の癖（2026-11、著者の環境での観測）

- アニメーションの再生はプラットフォームで差があります。Web では出ます。iOS では接続自体は成立しても星は出ませんでした。Android は、スクリーンショットの例があります
- 切断すると設定のコネクタ一覧（デフォルト表示）から消えます。未接続のカスタムコネクタは検索でしか出てこない仕様のようなので、再接続は設定画面の検索から探すのが近道です
- チャットで発行した接続リンクから再接続すると、そのチャットの会話が自動で再開され、Muse が起こされます。想定外の用途なので、これは仕様として受け入れています
